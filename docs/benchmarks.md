# UwDiff の実測（1.0.0）

外に出す数字の材料。どれも `tools/run_tests.sh` と同じ試験データ（`tools/testdata/uwdiff_gen2.c` で作る。種は固定）で測った値で、
**結果が正解と完全に一致することを確かめたうえでの時間**。

## 測った環境

- MacBook Air（Apple M4・10 コア・メモリ 32GB）、macOS、データは外付け SSD
- uvd 1.0.0（.NET 10）。「1.1.0」の節だけは uvd 1.1.0 と 1.0.0 を同じ機械で交互に流した値（2026-11-03・macOS 26.3.1）。秒は `/usr/bin/time` の real、メモリは maximum resident set size
- **キャッシュを消していない**値（データを作った直後に続けて実行）。10GB × 2 本はメモリに収まらないので、cold に近い
- 測り方の決まり: 機種・ストレージを書く／OS をまたいで秒を比べない／1.5 倍未満の違いは「同等」とする

## 試験データ

CSV（列: 点名,X,Y,Z,種別,測点番号,観測日,備考）。新は旧から、削除・追加・修正（1 行で 1〜7 セル・全部の列・値→空と空→値）・続いた行の塊（1〜128 行）・点名の変更・引用符の中の改行を入れて作る。
新の行順は keep（旧と同じ）・local（4,096 行ごとに並べ替え）・shuffle（全部並べ替え）、文字コードは UTF-8（LF）・CP932（CRLF）。

| 大きさ | 旧の行数 | 正解の差分の行数 |
|---|---|---|
| 1GB | 1,053 万 | 25.7 万 |
| 10GB | 1 億 534 万 | 255.9 万 |

|---|---|---|---|---|

| 10GB | shuffle | 23.3 秒 | 22.3 秒 | 11.1〜11.5GiB |

## テキストの比較（`uvd 旧 新 -o 差分.diff`・unified diff）

| 大きさ × 2 本 | 行順 | 時間 | メモリ | 差分の行数（削除／追加） |
|---|---|---|---|---|
| 1GB | keep | 1.7 秒 | 0.36GiB | 12.8 万／12.8 万 |
| 10GB | keep | **20.7 秒** | **0.4GiB** | 127 万／127 万 |
| 10GB | local（ほぼ全行が違う最悪の組） | 110 秒 | 1.3GiB | 1 億 631 万／1 億 631 万 |

- 差分の小ささ: 同じデータで GNU diff と比べ、keep では同じか少し少なく（100MB で -13,091/+11,812 行 対 diff の値とほぼ同じ）、local では +0.5%。
- 正しさ: 出した差分を旧に当てると新とバイト単位で一致することを、10GB でも確かめた（`tools/testdata/check_unified.py`）。

## テキストの比較 1.1.0: 先頭から同じ部分を飛ばす

1.1.0 から、旧と新の先頭から同じ部分は、行に切らずハッシュも付けずに、バイト列のまま比べて飛ばす（GNU diff の先頭の切り落としと同じ考え。違いの手前の文脈の行だけは普通に比べる）。差分は 1.0.0 とバイト単位で同じ。

同じ機種で 1.0.0 と 1.1.0 を交互に流した値（秒は中央値。1GB は 5 回・10GB は 3 回。キャッシュを消していない）。新は旧（`old_utf8.csv`）から作った: same＝同じ、tail＝最後の 0.1% の中の 10 行を変えて 1,000 行を足す（ログの追記の想定）、mid＝ちょうど半分の所の 1 行だけ違う。keep・local は上の表と同じデータ。

| 大きさ × 2 本 | 新 | 1.0.0 | 1.1.0 | メモリ 1.0.0 → 1.1.0 | 飛ばした行 |
|---|---|---|---|---|---|
| 1GB | same | 0.70 秒 | **0.23 秒** | 309 → 79MiB | 1,112 万（全部） |
| 1GB | tail | 0.72 秒 | **0.26 秒** | 309 → 87MiB | 1,111 万 |
| 1GB | mid | 0.73 秒 | 0.57 秒 | 309 → 313MiB | 556 万 |
| 1GB | keep | 1.03 秒 | 1.05 秒 | 412 → 412MiB | 270 |
| 1GB | local | 10.2 秒 | 10.4 秒 | 1,166 → 1,180MiB | 0 |
| 10GB | same | 19.6 秒 | 19.6 秒 | 249 → 81MiB | 1 億 1,120 万（全部） |
| 10GB | tail | 19.7 秒 | 19.6 秒 | 249 → 85MiB | 1 億 1,109 万 |
| 10GB | mid | 19.8 秒 | 19.7 秒 | 259 → 251MiB | 5,564 万 |
| 10GB | keep | 20.7 秒 | 20.8 秒 | 405 → 382MiB | 270 |
| 10GB | local | 106 秒 | 104 秒 | 1,321 → 1,320MiB | 0 |

- **10GB は時間が変わらない**: 2 本で約 20GB を読む時間（外付け SSD で約 20 秒）で決まっていて、1.0.0 も読む時間とほぼ同じだったため。減ったのは CPU 時間とメモリ（10GB same: user 11.1 → 1.1 秒・sys 5.4 → 3.0 秒〔各 1 回〕、メモリ約 3 分の 1）。
- 1GB（キャッシュに載る）で先頭から同じ部分が長いときは約 3 倍。違いが全体に散らばる組（keep・local）は 1.0.0 と同等（1.5 倍未満）。
- 正しさ: 全部の組・全部の回で 1.1.0 の差分が 1.0.0 の差分とバイト単位で一致。10GB local 以外は、差分を旧に当てると新とバイト単位で一致することも確かめた（`tools/testdata/check_unified.py`）。読む塊の境目の前後で違うときの試験は `tools/textcases.py`。

## 再現のしかた

```
DATA=<試験データの置き場所> tools/run_tests.sh 1GB 10GB
```

10GB は試験データだけで約 90GB 使う。
