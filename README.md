# UwDiff（UVD）

どんな形式・文字コード・OS でも、多数・巨大ファイルを高速に比べる道具（開発中）。

> **いまは段階 1（表の比較・CLI）**: CSV・TSV のキー照合と、採った変更の反映（`uvd apply`）。
> テキストの比較（段階 2）・圧縮／Word／Excel／PDF・フォルダ対フォルダ（段階 3）・GUI（段階 4）はまだ無い。
> 構文・出力の形は段階 1 の時点のもの（GUI と合わせて見直す）。ライセンスは公開前に置く。

## 構成

| 場所 | 中身 |
|---|---|
| `src/UwDiff.Core/` | 照合エンジン（`Diff/KeyedDiffEngine.cs` ほか）・反映（`Apply/ApplyEngine.cs`）・表のファイルの形（`CsvFile.cs`）・CSV の切り分け・文字コードの判定 |
| `src/Uvd.Cli/` | CLI `uvd` |
| `tools/edgecases.py` | 危ないところの確かめ（引用符の中の改行・キーの重複・文字コード 5 種と旧新の違い・TSV・複数列のキー・旧だけ／新だけの列・一時ファイルへの逃がし・反映） |
| `tools/run_tests.sh` | **試験の自動実行**（ビルド → 危ないところ → 試験データ 第 2 版で照合・逃がし・反映 → 正解と突き合わせ → 合否のまとめ） |
| `tools/testdata/` | 試験データ 第 2 版の生成器（`uwdiff_gen2.c`）・生成器の確かめ（`reference_diff.py`）・正解との突き合わせ（`check_answer.py`） |
| `tools/bench_mac.sh` | Mac での速さの計測（試験データ 第 1 版） |

## 使い方

```
dotnet build -c Release
src/Uvd.Cli/bin/Release/net10.0/uvd 旧.csv 新.csv -key 点名 -o 差分.csv
src/Uvd.Cli/bin/Release/net10.0/uvd apply 旧.csv 新.csv 採る差分.csv -o 結果.csv
```

### 照合 `uvd 旧 新 -key 列名 [-o 差分.csv]`

- 出力は `区分,キー列…,列,旧値,新値`（UTF-8）。区分は 追加・削除・変更（変わったセルごとに 1 行）。キーが複数列なら、キーの列がその数だけ並ぶ。
- **キー**: 見出しの名前か `#1` のような列番号。複数列は `-key 点名,種別`（または `-key` を繰り返す）。列の位置が旧と新で違ってもよい。
- **列**: 見出しの名前で対応付ける（並びが違ってもよい）。旧にしか無い列は新を空、新にしか無い列は旧を空として比べる。
- **文字コード**: UTF-8・CP932・EUC-JP・UTF-16LE／BE（BOM あり・なし）を自動判定。`-enc`（両方）・`-enc-old`・`-enc-new` で固定できる。
  - 旧と新が同じ文字コード（UTF-8・CP932・EUC-JP）なら、変換せずバイト列のまま比べる（速い）。
  - 違えば両方を UTF-8 にそろえて比べる。UTF-16 は区切りや改行をバイトで見分けられないので、同じどうしでも UTF-8 に直す。
- **区切り**: `.tsv`・`.tab` はタブ、`.csv` はカンマ、ほかは見出しの行のタブとカンマの数で決める。`-d tab` などで固定。旧と新で違ってもよい。
- **引用符**: CSV の決まりどおり（`"` で囲む・`""` は中の `"`・囲みの中の改行は行の区切りにしない）。引用符を使わない TSV は `-quote off`。
- **メモリの上限**: 待ち行（相手がまだ来ていない行）が `-mem`（既定は実メモリの 4 割）を超えたら、区画ごとに一時ファイル（`-tmp`、既定は OS の一時フォルダ）へ逃がし、読み終えた後にそこから照合する。止まらないが遅くなる。
- `-json 結果.json` で要約を JSON に書く。`-h` で全部のオプション。

### 反映 `uvd apply 旧 新 差分.csv -o 結果`

照合の差分から、**採らない行を消した**ものを旧に当てて、新しいファイルを書き出す（元のファイルは変えない）。

- 削除: そのキーの行を書かない。変更: そのセルだけを新値にする。追加: 新からそのキーの行を取り、旧の列の並びに直して末尾に足す。
- 旧の**文字コード・BOM・区切り・改行・引用符・行の順番**を保つ。変えない行はバイト列のまま写す。変えたセルは、元が引用符つきなら引用符つきで書く。
- 変更は、旧の今の値が差分の旧値と同じときだけ当てる（違えば当てずに知らせる）。新値が旧の文字コードで書けないとき、キーが見つからないとき、旧に無い列への変更も、当てずに知らせる。どれかがあれば終了コード 1（結果のファイルは書く）。
- キーが重複していれば、同じキーの行すべてに当てる。
- 差分は Excel で開いて行を消し、保存し直したもの（CP932・タブ区切り・UTF-16）でも読む。

## 試験

```
./tools/run_tests.sh                 # 10MB・100MB（数十秒）
./tools/run_tests.sh 1GB 10GB        # 大きいもの（10GB は 1 本で 10GB・全部で約 90GB のデータを作る）
```

- 試験データの置き場所は `DATA=…` で指定する（既定は `out/testdata`）。いつも同じ場所を使うなら、`tools/local.env` に `DATA=…` と書いておく（Git には入れない）。

- 試験データ 第 2 版は、削除・追加・修正（1 行で 1〜7 セル・全部の列・値→空と空→値）・続いた行の塊（削除・修正・点名変更・追加が 1〜128 行続く）・点名の変更（削除＋追加）・引用符の中の改行を含み、新の行順を keep（旧と同じ）・local（4096 行ごとに並べ替え）・shuffle（全部並べ替え）の 3 通り、文字コードを UTF-8・CP932 の 2 通りで作る。生成器の正解は、100MB 以下では Python の csv による照合でも確かめる。
- 大きさごとに、照合（3 通り × 2 文字コード）・逃がし（`-mem` をファイルの 5% にして行順ばらばらで照合）・反映（正解の差分を全部当てて新と照合し直し、差分 0・文字コードと改行が旧のまま）を確かめる。
- 危ないところ（`edgecases.py`）は 3,000 行と、10 万行を塊 1MB で（塊の境目をまたぐ行を多くする）。

## 方式

1. 旧・新を同時に先頭から 1 回だけ読む（32MB ずつ。片方が先に進みすぎないよう歩調を合わせる）。
2. 行に切り（引用符の中の改行は行の区切りにしない）、キーのハッシュで区画に振り分ける。
3. 区画ごとに 1 つの照合スレッドが、相手側の待ち行に同じキーがあれば突き合わせて捨て、無ければ待ち行に入れる。
4. 比べるのはバイト列のまま。CP932 の 2 バイト目・EUC-JP の各バイトは `"`・`,`・タブ・改行と重ならないので、変換せずに区切れる。
5. 待ち行の合計がメモリの上限を超えたら、その区画の待ち行を一時ファイルへ逃がし、以後その区画の行は一時ファイルへ書く。読み終えた後、一時ファイルから照合する（大きすぎればキーのハッシュの別のビットで 16 に分けてから）。
6. 読み終えたら、残った待ち行が削除（旧）と追加（新）。キーの重複は、キーのハッシュを区画ごとに記録し（メモリは 512MB まで、超えた分は一時ファイル）、最後に区画ごとに並べて数える。

反映は、差分だけをメモリに持ち、旧と新を 1 回ずつ順に読む。
